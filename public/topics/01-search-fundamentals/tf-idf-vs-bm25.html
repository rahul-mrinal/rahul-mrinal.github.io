01 The Contenders

Two algorithms dominate keyword-based search. One came first and built the foundation. The other refined it into the most widely deployed ranking function on earth.

TF-IDF

Born in the 1970s. Simple, elegant multiplication: how often a term appears in a doc times how rare it is across all docs. The foundation of information retrieval.

  • Linear term frequency
  • No length normalization
  • No saturation curve

BM25

Developed in the 1990s by Robertson & Sparck Jones. Probabilistically motivated upgrade that fixes TF-IDF's biggest weaknesses. Powers Elasticsearch, Lucene, Solr.

  • Saturating term frequency
  • Built-in length normalization
  • Tunable parameters \(k_1\) and \(b\)
🥊

Analogy: TF-IDF is like counting how many times a student mentions a topic in their essay. BM25 is like a smarter grader who knows that mentioning "machine learning" 50 times doesn't make an essay twice as good as one that mentions it 25 times — and who also adjusts for essay length.

02 TF-IDF Formula

TF-IDF multiplies two components: how frequent a term is locally, and how rare it is globally.

$$\color{#6c63ff}{\text{TF-IDF}(t,\, d)} \;=\; \underbrace{\color{#6c63ff}{f(t,d)}}_{\text{term frequency}} \;\times\; \underbrace{\color{#00c9a7}{\ln\!\left(\frac{N}{\text{df}(t)}\right)}}_{\text{inverse doc frequency}}$$
\(f(t,d)\) = count of term \(t\) in doc \(d\)  •  \(N\) = total documents  •  \(\text{df}(t)\) = documents containing \(t\)

Components

Term Frequency (TF)

Raw count of how many times the query term appears in the document. More mentions = higher score. Grows linearly — this is the weakness BM25 fixes.

Inverse Document Frequency (IDF)

Measures how rare a term is. "the" appears everywhere (low IDF). "eigenvalue" appears rarely (high IDF). Rare terms are more discriminative.

The log-TF variant

Some implementations use \(1 + \ln(f(t,d))\) instead of raw \(f(t,d)\) to slightly dampen TF growth, but it still doesn't saturate like BM25.

03 BM25 Formula

BM25 adds two critical improvements: TF saturation and length normalization.

$$\color{#6c63ff}{\text{BM25}(q,\, d)} \;=\; \sum_{t \,\in\, q} \;\color{#00c9a7}{\text{IDF}(t)} \;\cdot\; \frac{\color{#6c63ff}{f(t,d)} \;\cdot\; (\color{#ffd93d}{k_1} + 1)}{\color{#6c63ff}{f(t,d)} \;+\; \color{#ffd93d}{k_1} \;\cdot\; \left(1 - \color{#ff6b6b}{b} + \color{#ff6b6b}{b} \;\cdot\; \dfrac{|d|}{\text{avgdl}}\right)}$$
\(\color{#ffd93d}{k_1}\) controls saturation speed  •  \(\color{#ff6b6b}{b}\) controls length normalization strength

What makes BM25 better?

Saturation

The TF component \(\frac{f \cdot (k_1+1)}{f + k_1}\) approaches a maximum as frequency increases. The 10th mention of "python" adds far less than the 1st. This prevents keyword stuffing from gaming rankings.

Length Normalization

The denominator includes \(\frac{|d|}{\text{avgdl}}\), which penalizes documents longer than average. A 10,000-word doc mentioning "python" 50 times gets a lower score than a 200-word doc mentioning it 10 times.

05 Long Document Bias

Longer documents naturally contain more term occurrences. TF-IDF rewards them unfairly. BM25 normalizes for length.

08 When to Use What

Scenario TF-IDF BM25 Winner
General web search Biased toward long pages Normalizes for length BM25
Short uniform docs (tweets, titles) Works fine Slight advantage BM25
Feature extraction for ML Standard choice Less common TF-IDF
Spam / keyword stuffing Easily gamed Saturates — resistant BM25
Mixed-length corpora Poor — long docs dominate Length-normalized BM25
Simplicity / teaching Simpler to understand More parameters TF-IDF
Production search engines Outdated for ranking Industry standard BM25
Bottom line:

Use TF-IDF for feature engineering in ML pipelines and for educational purposes. Use BM25 for any production search or ranking system. BM25 is strictly better for search — it's what Elasticsearch, Lucene, and Solr all default to.

09 Key Takeaway

BM25 = TF-IDF + Saturation + Length Normalization

BM25 isn't a completely different algorithm — it's a principled refinement of TF-IDF. The two key improvements are:

  1. Term frequency saturation — Diminishing returns from repeated terms, preventing keyword stuffing
  2. Document length normalization — Fair comparison between short focused docs and long unfocused ones

Every modern search engine uses BM25 (or a variant). Understanding the why behind each component makes you a better search engineer.
