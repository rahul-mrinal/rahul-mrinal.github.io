01 Why Metrics Matter

You can't improve what you can't measure. Search quality is subjective, but metrics make it objective.

📊

Analogy: Imagine tuning a search engine by feel — "the results look okay." That's like optimizing a car engine by listening to it purr. Metrics are the dashboard gauges: RPM, temperature, fuel efficiency. They tell you exactly what's working and what's not, so you can make targeted improvements.

Compare algorithms

Is BM25 better than TF-IDF for your corpus? Metrics give you a definitive answer.

Track regressions

Did your latest change to the ranking pipeline make things worse? A/B test with metrics.

Guide optimization

Low precision? Add better filtering. Low recall? Expand query terms. Metrics tell you where to focus.

02 Precision

Of the documents you returned, how many were actually relevant?

$$\color{#6c63ff}{\text{Precision@K}} \;=\; \frac{\color{#00c9a7}{\text{Relevant documents in top-K}}}{\color{#ffd93d}{K}}$$
High precision = few irrelevant results shown to the user
Precision = 1.0

Every result you showed was relevant. Perfect — but you might have missed some relevant docs (low recall).

Precision = 0.2

Only 1 in 5 results was relevant. The user wastes time scanning through junk. Terrible experience.

Example

Query: "Python async tutorial." You return 5 results. 3 are about Python asyncio, 1 is about JavaScript promises, 1 is about Python basics.

Precision@5 = 3 relevant / 5 returned = 0.60

03 Recall

Of all the relevant documents that exist, how many did you actually find?

$$\color{#6c63ff}{\text{Recall@K}} \;=\; \frac{\color{#00c9a7}{\text{Relevant documents in top-K}}}{\color{#ff6b6b}{\text{Total relevant documents in corpus}}}$$
High recall = you didn't miss important relevant documents
Recall = 1.0

You found every relevant document. But you might have also returned a lot of irrelevant ones (low precision).

Recall = 0.1

You only found 10% of the relevant docs. The user is missing 90% of what they need.

The Precision-Recall Trade-off

Returning more results tends to increase recall but decrease precision. Returning fewer results does the opposite. The "right" balance depends on your use case: legal discovery needs high recall (find everything), web search needs high precision (top results must be great).

05 F1 Score

The harmonic mean of precision and recall — a single number that balances both.

$$\color{#ffd93d}{\text{F1}} \;=\; 2 \;\cdot\; \frac{\color{#6c63ff}{\text{Precision}} \;\cdot\; \color{#00c9a7}{\text{Recall}}}{\color{#6c63ff}{\text{Precision}} \;+\; \color{#00c9a7}{\text{Recall}}}$$
Harmonic mean — punishes extremes more than arithmetic mean

Why harmonic mean?

The arithmetic mean of Precision=1.0 and Recall=0.0 is 0.5 — misleadingly high for a useless system. The harmonic mean gives 0.0, correctly reflecting that the system fails completely on one dimension.

When to use F1

Use F1 when you need a single summary metric and both precision and recall matter equally. In practice, you often care more about one than the other — in which case, look at them individually or use F-beta.

06 MRR (Mean Reciprocal Rank)

How quickly does the user find the first relevant result?

$$\color{#6c63ff}{\text{MRR}} \;=\; \frac{1}{|Q|} \sum_{i=1}^{|Q|} \frac{1}{\color{#00c9a7}{\text{rank}_i}}$$
\(|Q|\) = number of queries  •  \(\color{#00c9a7}{\text{rank}_i}\) = position of the first relevant result for query \(i\)
🎯

Analogy: MRR measures how many results the user has to scan before finding a good one. If the first result is always relevant (rank 1), MRR = 1.0. If users typically have to scroll to the 5th result, MRR = 0.2. It captures the "I'm feeling lucky" quality of your search engine.

08 NDCG (Normalized Discounted Cumulative Gain)

The gold standard metric for graded relevance — not just binary relevant/irrelevant, but how relevant.

Step 1: Cumulative Gain (CG)

$$\color{#6c63ff}{\text{CG@K}} \;=\; \sum_{i=1}^{K} \text{rel}_i$$
Sum of relevance grades — ignores position

Step 2: Discounted Cumulative Gain (DCG)

$$\color{#6c63ff}{\text{DCG@K}} \;=\; \sum_{i=1}^{K} \frac{\color{#00c9a7}{2^{\text{rel}_i} - 1}}{\color{#ff6b6b}{\log_2(i + 1)}}$$
\(\color{#00c9a7}{2^{\text{rel}_i}-1}\) = gain from relevance grade  •  \(\color{#ff6b6b}{\log_2(i+1)}\) = position discount (lower ranks count less)

Step 3: Ideal DCG (IDCG)

$$\color{#ffd93d}{\text{IDCG@K}} \;=\; \text{DCG@K of the perfect ranking (sort by relevance desc)}$$
The best DCG you could possibly achieve

Step 4: NDCG

$$\color{#6c63ff}{\text{NDCG@K}} \;=\; \frac{\color{#6c63ff}{\text{DCG@K}}}{\color{#ffd93d}{\text{IDCG@K}}}$$
Normalized to [0, 1] — 1.0 means perfect ranking
Why graded relevance?

Binary metrics treat all relevant documents equally. But a "highly relevant" doc at position 3 is worse than a "perfectly relevant" doc at position 1. NDCG captures these fine distinctions with grades like 0 (irrelevant), 1 (marginally relevant), 2 (relevant), 3 (highly relevant).

10 Metric Comparison

Metric Measures Relevance Type Position-Aware Best For
Precision@K How clean the results are Binary No Web search, user-facing results
Recall@K How complete the results are Binary No Legal discovery, medical search
F1 Balance of P and R Binary No Single summary metric
MRR Speed to first relevant result Binary Yes (first only) Q&A, navigational search
NDCG@K Ranking quality with graded relevance Graded (0–3+) Yes (all positions) General ranking evaluation
MAP Average precision across recall levels Binary Yes (all positions) Information retrieval benchmarks
For most search systems, use NDCG

NDCG is the most informative metric. It handles graded relevance, cares about position, and normalizes to a 0-1 scale. Most search competitions (TREC, Kaggle) use NDCG as the primary metric.

Quick sanity check: Precision@5

If you need a quick, intuitive metric, Precision@5 tells you "of the first 5 results, how many are good?" Stakeholders understand it immediately.

11 Key Takeaway

Match the metric to the task

There is no single "best" metric — each captures a different aspect of search quality:

  • Precision when showing garbage results is unacceptable (e-commerce, ads)
  • Recall when missing a relevant result is costly (legal, medical, security)
  • MRR when users just need the one right answer (Q&A, autocomplete)
  • NDCG when ranking order matters and relevance isn't binary (web search, recommendations)

In practice, track multiple metrics simultaneously. A change that improves NDCG but tanks Precision@1 probably isn't worth it.
