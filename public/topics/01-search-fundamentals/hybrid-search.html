Hybrid Search: Best of Both Worlds

Combine keyword precision with semantic understanding

01 The Problem

Neither keyword search nor semantic search is perfect alone. Each has blind spots the other covers.

Keyword search misses meaning

A user searches for "automobile repair" but your documents say "car maintenance." BM25 finds zero matches because the exact words don't appear. The meaning is identical, but keyword search is blind to synonyms.

Semantic search misses exact terms

A user searches for "Python 3.12 asyncio bug." Semantic embeddings might return general async programming docs. The exact version number "3.12" and specific term "asyncio" get lost in the embedding space.

🔍

Analogy: Keyword search is like a librarian who only finds books by matching exact words in the title. Semantic search is like a librarian who understands what you mean but sometimes grabs a book about a related topic instead of the exact one you need. The best library uses both: find exact matches AND semantically similar ones.

BM25 Path

Uses an inverted index to find documents containing query terms. Scores based on term frequency, document frequency, and document length. Fast, precise, interpretable.

Vector Path

Encodes the query into a dense vector using an embedding model (e.g., sentence-transformers). Searches an ANN index (HNSW, IVF) for nearest neighbors. Captures semantic meaning.

03 The Score Fusion Challenge

You can't simply add BM25 and vector scores — they live on completely different scales.

BM25 Scores

Range: 0 to ~25+. Unbounded. Depends on corpus size, term rarity, document length. A score of 8.3 is meaningless without context.

Doc A: 12.4   Doc B: 8.1   Doc C: 3.2
Vector Scores (Cosine Similarity)

Range: -1 to 1 (typically 0.5 to 0.99). Bounded. Depends on embedding model quality and dimensionality.

Doc A: 0.91   Doc B: 0.87   Doc C: 0.82
Why not just normalize?

You can min-max normalize both to [0,1] before combining, but this is fragile: the normalization depends on the current result set and changes with every query. Two principled approaches have emerged: Reciprocal Rank Fusion (RRF) and Linear Combination with normalization.

04 Reciprocal Rank Fusion (RRF)

RRF elegantly sidesteps the score calibration problem by using only ranks, not scores.

$$\color{#6c63ff}{\text{RRF}(d)} \;=\; \sum_{r \,\in\, R} \frac{1}{\color{#ffd93d}{k} + \color{#00c9a7}{\text{rank}_r(d)}}$$
\(R\) = set of rankers  •  \(\color{#ffd93d}{k}\) = smoothing constant (default 60)  •  \(\color{#00c9a7}{\text{rank}_r(d)}\) = rank of doc \(d\) in ranker \(r\) (1-based)

Why RRF works

Score-agnostic

Only uses position, not the raw score. BM25 scores of 12.4 and cosine of 0.91 aren't compared — only their ranks.

Robust to outliers

The \(k\) constant prevents top-ranked documents from dominating. With \(k=60\), rank 1 gets \(\frac{1}{61}\) vs rank 2's \(\frac{1}{62}\) — a tiny difference.

Rewards consensus

Documents ranked highly by both rankers get the highest fused scores. A doc ranked #1 in BM25 and #3 in vector beats one ranked #1 in BM25 but #50 in vector.

Example Calculation

Doc "Python Tutorial" is ranked #2 in BM25 and #1 in Vector (with \(k=60\)):

RRF = 1/(60+2) + 1/(60+1) = 0.01613 + 0.01639 = 0.03252

06 Linear Combination

An alternative to RRF: normalize scores to [0,1] and blend with a weight \(\alpha\).

$$\color{#6c63ff}{\text{score}(d)} \;=\; (1 - \color{#ffd93d}{\alpha}) \;\cdot\; \color{#6c63ff}{\hat{s}_{\text{BM25}}(d)} \;+\; \color{#ffd93d}{\alpha} \;\cdot\; \color{#00c9a7}{\hat{s}_{\text{vector}}(d)}$$
\(\hat{s}\) = min-max normalized score  •  \(\color{#ffd93d}{\alpha} = 0\) → all BM25  •  \(\color{#ffd93d}{\alpha} = 1\) → all vector

09 Key Takeaway

Hybrid search consistently outperforms either method alone

Research and production experience both confirm: combining keyword and semantic retrieval gives the best results. The fusion method matters less than the decision to combine.

  1. RRF is the go-to choice — no hyperparameters to tune (k=60 works great), score-agnostic, robust
  2. Linear combination gives more control but requires tuning \(\alpha\) per use case
  3. Cross-encoder re-ranking on top of hybrid retrieval gives the best quality when latency allows
