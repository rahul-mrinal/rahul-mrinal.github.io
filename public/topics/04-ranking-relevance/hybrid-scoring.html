Three production approaches to combining BM25 and vector scores

01 The Scale Problem

BM25 and vector search produce scores on completely different scales. Naively adding them together lets one signal dominate the other.

BM25 Scores

Range: 0 to ~25+

Unbounded — depends on term frequency, document length, and corpus statistics. A score of 12.5 is typical for a good match; rare-term matches can exceed 20.

Example scores
"machine learning" → 14.2
"python tutorial" → 8.7
"the" → 0.3

Cosine Similarity

Range: -1 to 1 (normalized vectors: 0 to 1)

Bounded — always between -1 and 1. Most embedding models produce non-negative scores, so practical range is 0 to 1. A score of 0.85 is a strong semantic match.

Example scores
"ML algorithms" → 0.91
"coding guide" → 0.72
"weather today" → 0.15
⚖️

Analogy: Imagine combining a temperature in Fahrenheit (70°F) with a score out of 10 (8/10). Adding them gives 78, where the temperature dominates. You need to put both on the same scale first — that's what normalization does.

$$\text{naive\_score} = \underbrace{14.2}_{\text{BM25}} + \underbrace{0.91}_{\text{cosine}} = 15.11$$

BM25 contributes 94% of the final score — vector similarity is nearly irrelevant

Score Distribution Comparison

Understanding how each retriever distributes its scores is critical for choosing a fusion method:

Property BM25 Cosine Similarity
Theoretical Range 0 to ∞ (unbounded) -1 to 1 (bounded)
Practical Range 0 to ~25 0.1 to 0.99
Distribution Shape Right-skewed, long tail Roughly normal, centered ~0.5
Zero Score Meaning No term overlap Orthogonal (unrelated)
Sensitive To Term rarity, doc length Embedding model quality
Query-Dependent Yes — varies by corpus stats Less — normalized vectors
Real-World Observation

In production systems at Airbnb and LinkedIn, BM25 scores for top results typically cluster between 8 and 18, while vector similarities cluster between 0.7 and 0.95. The gap in magnitude is the core problem that fusion methods must solve.

02 Method 1: Min-Max + Weighted Sum

Normalize both score sets to [0, 1], then combine with a tunable weight parameter α.

Step 1: Min-Max Normalization

For each retrieval method independently, scale all scores so the lowest becomes 0 and the highest becomes 1:

$$\text{norm}(s) = \frac{s - s_{\min}}{s_{\max} - s_{\min}}$$

Applied separately to BM25 scores and vector scores

Step 2: Weighted Combination

Use parameter $\alpha \in [0, 1]$ to control the balance:

$$\text{hybrid}(d) = \alpha \cdot \text{norm\_bm25}(d) + (1 - \alpha) \cdot \text{norm\_vec}(d)$$

α = 1 → pure BM25, α = 0 → pure vector, α = 0.5 → equal weight

Pros

  • Simple to implement and understand
  • One tunable parameter (α)
  • Works well when score distributions are similar

Cons

  • Sensitive to outliers (one very high BM25 score compresses others)
  • Requires scores from both retrievers for every document
  • Normalization is query-dependent — hard to compare across queries

03 Method 2: Reciprocal Rank Fusion (RRF)

Ignore scores entirely — combine using only rank positions. Originally proposed by Cormack et al. (2009).

$$\text{RRF}(d) = \sum_{r \in \text{retrievers}} \frac{1}{k + \text{rank}_r(d)}$$

k is a smoothing constant (typically 60). rank is 1-based position.

Why Ranks Instead of Scores?

Scores from different retrievers have different distributions, scales, and meanings. Ranks are universal — position 1 is always the best result, regardless of the retriever.

🏆

Analogy: Imagine two judges scoring a cooking competition. Judge A uses a 0-100 scale, Judge B uses a 0-5 scale. Instead of averaging their raw scores, you average their rankings. If both judges ranked a dish #1, it's the clear winner — regardless of the actual scores.

The k Parameter

The constant $k$ controls how much weight is given to lower-ranked documents:

Small k (e.g., 1)

Top-ranked documents dominate. Rank 1 gets score 0.50, Rank 2 gets 0.33 — a 34% drop.

Large k (e.g., 60)

Scores are more evenly distributed. Rank 1 gets 0.0164, Rank 2 gets 0.0161 — only a 2% drop.

Production Note

Elasticsearch, Weaviate, and most vector databases use $k = 60$ as the default. This value was empirically chosen in the original RRF paper and works well across domains.

RRF Worked Example

Two retrievers each return 5 documents. Let's compute RRF with $k = 60$:

Document BM25 Rank Vec Rank RRF(BM25) RRF(Vec) Total RRF
Doc A 1 3 $\frac{1}{61} = 0.0164$ $\frac{1}{63} = 0.0159$ 0.0323
Doc B 2 1 $\frac{1}{62} = 0.0161$ $\frac{1}{61} = 0.0164$ 0.0325
Doc C 3 5 $\frac{1}{63} = 0.0159$ $\frac{1}{65} = 0.0154$ 0.0312
Doc D 5 2 $\frac{1}{65} = 0.0154$ $\frac{1}{62} = 0.0161$ 0.0315
Doc E 4 4 $\frac{1}{64} = 0.0156$ $\frac{1}{64} = 0.0156$ 0.0313

RRF Final Ranking: Doc B (#1) → Doc A (#2) → Doc D (#3) → Doc E (#4) → Doc C (#5)

Notice: Doc B wins because it was ranked #1 by the vector retriever and #2 by BM25 — consistent high ranking beats being #1 in only one retriever.

Common Models

Linear Model

$\text{score} = w_1 \cdot \text{bm25} + w_2 \cdot \text{vec} + w_3 \cdot \text{freshness} + \ldots$

Fast, interpretable. Good starting point.

LambdaMART / XGBoost

Gradient-boosted trees optimized for NDCG. Captures non-linear interactions between features.

Industry standard at Google, Bing, Airbnb.

Requires Click Data

Learned fusion only works if you have enough user interaction data to train on. For new products or low-traffic search, start with RRF or weighted sum, then graduate to learned fusion once you have ~10k+ queries with clicks.

Training Labels from Clicks

Converting implicit feedback (clicks) into training labels for the LTR model:

Click-Skip Pairs

If a user skips result at rank 2 but clicks rank 3, we infer that doc 3 is more relevant than doc 2 for that query. This creates pairwise preferences for training.

# Pairwise label extraction
for click in session.clicks:
  for skip in session.skips:
    if skip.rank < click.rank:
      pairs.append((click.doc, skip.doc))

Dwell-Time Labels

Threshold dwell time into relevance grades:

  • Short click (<5s): grade 0 (misclick)
  • Medium dwell (5–30s): grade 1 (partial)
  • Long dwell (>30s): grade 2 (satisfied)
  • Purchase/bookmark: grade 3 (perfect)

Evaluation: NDCG

Measure your learned fusion model with Normalized Discounted Cumulative Gain:

$$\text{NDCG@k} = \frac{\text{DCG@k}}{\text{IDCG@k}} = \frac{\sum_{i=1}^{k} \frac{2^{\text{rel}_i} - 1}{\log_2(i+1)}}{\text{ideal DCG@k}}$$

NDCG = 1.0 means perfect ranking; typical production systems aim for 0.6–0.8

What to Look For

Score Sensitivity

Weighted Sum is sensitive to score magnitudes. One outlier BM25 score can dominate the ranking even at α = 0.5.

Rank Stability

RRF produces the most stable rankings — small changes in scores don't cause big rank swaps because it only uses ordinal positions.

08 Key Takeaway

The Bottom Line

There is no single best fusion method. RRF is the safest default — it's score-agnostic, outlier-resistant, and requires no tuning. Graduate to weighted sum when you understand your score distributions, and to learned fusion when you have enough click data to train on. The biggest mistake is not combining signals at all.
