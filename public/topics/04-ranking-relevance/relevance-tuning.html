01 Why Tune?

Default BM25 ranking treats all fields equally. In practice, a match in the title is far more valuable than a match deep in the description.

🎯

Analogy: Imagine searching for a book. If the word "Python" appears in the title, the book is almost certainly about Python. If it appears once in a 500-page description, it might be a passing mention. Relevance tuning teaches the search engine this difference.

Without Tuning

Query "wireless headphones" returns a laptop accessory guide (mentions "wireless headphones" once in a long description) above actual wireless headphones products.

With Tuning

Title-boosted search correctly ranks products with "wireless headphones" in their title at the top, followed by tag matches, then description matches.

02 Field Boosting

Weight different fields differently. A title match should count more than a description match.

$$\text{score}(d, q) = \sum_{f \in \text{fields}} \text{boost}_f \cdot \text{BM25}(d_f, q)$$

boost_f controls how much field f contributes to the total score

Typical Boost Ranges by Domain

Domain Title Boost Description Tags/Categories Body/Content
E-Commerce 5–8× 1× 3–4× 0.5×
Documentation 3–5× 1× 2× 1×
News Articles 4–6× 2× 1.5× 1×
Knowledge Base 3–4× 1.5× 2–3× 1×
🎛️

Analogy: Field boosting is like an audio mixer. Each field is a track (vocals, bass, drums). The boost slider controls how loud that track is in the final mix. Too much title boost and you drown out everything else; too little and important matches get buried.

03 Function Scoring

Combine text relevance with business signals — recency, popularity, and quality — to produce a composite score.

$$\text{final}(d) = w_r \cdot \text{relevance}(d) + w_f \cdot \text{freshness}(d) + w_p \cdot \text{popularity}(d)$$

Weights control the trade-off between relevance, recency, and popularity

Score Combination Strategies

Additive

$\text{final} = \text{rel} + w_f \cdot f(t) + w_p \cdot g(p)$

Functions add to the base relevance score. Simple and predictable. Use when business signals should nudge rankings, not override them.

Multiplicative

$\text{final} = \text{rel} \times (1 + w_f \cdot f(t)) \times (1 + w_p \cdot g(p))$

Business signals amplify relevance. A highly relevant but unpopular doc still scores well. A relevant + popular doc scores much higher.

Elasticsearch function_score

In Elasticsearch, use function_score query with score_mode: "sum" for additive or score_mode: "multiply" for multiplicative. Set boost_mode: "multiply" to apply the function result to the query score.

04 Recency Decay

Newer content should rank higher — but how fast should old content decay? Choose from linear, exponential, or Gaussian decay functions.

$$\text{linear}(t) = \max\left(0,\; 1 - \frac{t}{T}\right)$$

Score drops to 0 at time T

$$\text{exp}(t) = e^{-\lambda t}$$

Fast initial drop, long tail

$$\text{gauss}(t) = e^{-\frac{t^2}{2\sigma^2}}$$

Slow start, sharp drop at σ

Choosing a Decay Function

Function Behavior Best For Example
Linear Constant decay rate, reaches 0 Job listings, event schedules Score = 0 after 30 days
Exponential Fast initial drop, never reaches 0 News articles, social media 50% value after 3 days
Gaussian Gentle start, accelerating drop Blog posts, documentation Still 90% at 7 days, 30% at 30 days

05 Query-Time Boosting

Apply ad-hoc boosts for specific business rules without modifying the index or base ranking.

Common Use Cases

Promotional Boost

Boost products that are on sale or part of a campaign:

if doc.on_sale:
    score *= 1.5  # 50% boost

Category Pinning

When query matches a known category, boost that category:

if query_category == doc.category:
    score *= 2.0  # double the score

Geo Boost

Boost results that are geographically close to the user:

distance = haversine(user, doc)
geo_boost = 1.0 / (1 + distance / 50)

Penalty (Negative Boost)

Demote low-quality or out-of-stock items:

if doc.out_of_stock:
    score *= 0.1  # push to bottom
Keep It Auditable

Every query-time boost should be logged. When rankings look wrong, you need to trace which boosts fired and why. Build a "score explanation" endpoint that shows the breakdown for any result.

Statistical significance
Statistical Significance

Don't ship a tuning change based on 100 queries. You need statistical significance — typically p < 0.05 with at least 1,000–10,000 queries per variant. Use a two-proportion z-test for CTR or a paired t-test for NDCG.

Common Pitfalls

Position Bias

Users click the first result regardless of relevance. Use interleaving (mix control + treatment results in one list) to eliminate position bias.

Novelty Effect

New rankings might get more clicks simply because they look different. Run the test for at least 2 weeks to let the novelty wear off.

07 Tuning Workflow

A step-by-step process for systematically improving search relevance.

1

Establish a Baseline

Measure current NDCG@10, MRR, and CTR on a representative query set. This is your control.

2

Build a Judgment Set

Create 100–500 query-document pairs rated by humans (0 = irrelevant, 1 = partial, 2 = relevant, 3 = perfect). Use these for offline evaluation.

3

Tune One Variable at a Time

Start with field boosts, then function scores, then query-time boosts. Measure each change independently against the baseline.

4

Offline Evaluation

Run your judgment set through the new config. Compare NDCG@10 with the baseline. If it improves by >2%, proceed to A/B test.

5

A/B Test in Production

Split traffic 50/50. Run for 2+ weeks. Ship only if the treatment shows statistically significant improvement.

6

Monitor & Iterate

Search quality degrades over time as content changes. Re-evaluate monthly and retune quarterly.

08 Key Takeaway

The Bottom Line

Relevance tuning is not a one-time task — it's a continuous feedback loop. Start with field boosting (title > tags > description), add function scoring for business signals (recency, popularity), and validate every change with A/B tests. The goal is not perfect ranking — it's measurably better ranking than what you had yesterday.

Quick Wins

  • Boost title matches 3–5× over description
  • Add recency decay for time-sensitive content
  • Demote out-of-stock or deprecated items

Advanced

  • Train LTR models on click data
  • Interleaved A/B testing for unbiased evaluation
  • Per-category tuning profiles
